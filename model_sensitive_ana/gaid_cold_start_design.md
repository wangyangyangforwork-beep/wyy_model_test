# GAID 新人高估：几套可以分开做的模型方案

日期：2026-11-24。数字来自评测纪要《GAID 空初始化与实时点击特征滞后》，这里不重跑。

## 这件事在说什么

模型给「这个人会不会买」打分时，很依赖两样东西：

1. **这个 GAID 自己的一串向量**（slot 3，`req_gaid`）。老人点了很多次却很少买，这串向量会把他的分往下拉。
2. **最近点了多少次**（4001 的 24 小时点击、902 的 session）。绿带实验里，这类点击统计本来就是压分、拉排序的主力。

线上两类人经常两样都没有：

- GAID 没进已发布的表，向量被填成 **全 0**。
- 点击其实已经发生了，4001 / 902 仍是 0。`v4001=0` 的行里，**93% 不是当天第一下**，**将近一半**来自当天点了 32 次以上的人。

结果就是双空格（4001 和 902 都是 0）预估比实际高大约 **一倍**（cvr_diff **+102%**），并且占了正 excess 的 **七成**。

有一个对照把原因钉死了：同一批人，等当天样本训进模型（8e8），双空格只剩 **+12%**；再把这版模型的 GAID 向量人为改成 0，又回到 **+102%**。分是被 GAID 那一行拉下来的。线上新人走的就是「向量为 0」这条，不是「已经训过」那条。

8e8 的 +12% 不能当成新人上线后的效果。那一版模型在评估当天已经见过这些人的购买标签。它只说明：这行向量**有能力**记住这批人。线上要等下一版发布才读得到。

转化率很低（工具订阅整体大约 0.035%）。一个人点几十次、一次没买，并不足以单独证明他比平均更差。1108 当天 `v4001=0` 有 42.8 万行，双空大约占其中 17%，**这一格的平均水平**估得准。所以新人第一天靠格子，一个人自己的向量留到下一版再用。

还有一条约束：样本是点击之后的 CVR。点击发生的那一下，购买结果还没出来，**这一下本身不是负样本**。请求时也经常不知道「点击样本生成了没有」。方案里凡是写「负反馈」的，都是下面两种之一：很多用户共享的一档分数，或者等样本入库之后、下一版才生效的个人统计。不在点击瞬间给 GAID 记一笔负分。

## 方案一览

| 方案 | 一句话 | 要不要新基建 | 新人之间有没有差别 |
|---|---|---|---|
| A. 新人扣分表 | 向量为 0 时，logit 上按格子减一截 | 不用，先离线就能验 | 只有格子那么粗 |
| B. 训练按线上来 | 训练时，还没发布的 GAID 不用他的私有向量 | 改训练，serving 换掉全 0 | 取决于下面叠哪张表 |
| C. 新人共享向量 | 全 0 换成学出来的默认向量，再加人群 | 改训练和查表 | 有，按媒体、地域、设备档、小时 |
| D. 已发布点击次数 | 用样本管道里的次数代替迟到的 4001 | 一张小计数表 | 有，按点了几次 |
| E. 请求次数 | 请求进模型时自己计数，不看展示回传、也不看点击 | 请求入口计数，并打进样本 | 有，按请求档 |
| F. 新人小网络 | 老人走原模型，新人走另一个小头 | 多一个头 | 有，靠上下文 |
| G. 把老人的压分蒸馏出来 | 用上下文去预测「若有 GAID 向量会减多少分」 | 多一个小头 | 有，靠上下文 |

A 到 E 是主体。F、G 是 A 不够用时的加项。B 是训练合同，建议和其中一张表一起做，否则下一次全量训练会把单独加的表抵消掉。行业一维偏置那次，和主体一起训，修正被挤到大约 +0.03，就是这个现象。双空格这一格大约差 **0.7 的 logit**（预估是实际的 2 倍，转化率又很低），量级大，更要冻住主体来拟合，或者让主体在训练时就看见和线上一样的输入。

下面每套都写：做什么、适合什么、代价、做成什么样算对。

## 方案 A：新人扣分表

这张表不是新的 MMoE，也不要当成普通特征送进现在的网络。送进网络里、再和主体一起训，行业偏置那次已经试过，修正会被挤掉。

结构就一件事：现在的购买 logit 冻住，后面加 8 个数里的一个。

```text
特征 → embedding → MMoE → 购买 logit（整段冻住，停止梯度）
                              │
                              └── + b[三档开关拼出来的 8 选 1]
                                        │
                                     sigmoid
```

三个开关，每个只有 0/1：

- `gaid_cold`：线上是「这个 GAID 不在已发布的表里」。离线探针先用现成的 `mask_groups=req_gaid`，把 slot 3 置 0，同时把这个开关打成 1。
- `e4001`：4001 是不是 0。
- `e902`：902 是不是空。

8 个数各自独立，用 FTRL，每个就是一个 1 维偏置。不要拆成「gaid 一个数 + 4001 一个数 + 902 一个数」再相加。mask 实验里四个格子差得很远，相加拟合不了：

| gaid_cold | 4001=0 | 902 空 | mask 之后的 cvr_diff | 这格要学的 |
|---|---|---|---|---|
| 1 | 0 | 0 | +7.0% | 接近 0 |
| 1 | 1 | 0 | +37.5% | 单独一个数 |
| 1 | 0 | 1 | +58.2% | 单独一个数 |
| 1 | 1 | 1 | +101.5% | 大约 −0.7 的 logit，用样本重算 |

`gaid_cold=0` 的另外 4 格先固定为 0。老人的向量还在，不靠这张表。

落到现有槽位上：新开一个 slot，一条样本只落一个 fid，fid 就是上面 8 种组合之一，embedding 维度是 1，加到购买 logit 上，不进 MMoE。

训练步骤：

1. 加载现有 checkpoint，除了这 8 个数，全部冻住。
2. 每条样本把 slot 3 置 0，按 4001、902 拼出 fid，前向，用原来的 CVR 交叉熵。
3. 再加一项格子均值：这一格的平均预估对齐平均标签。交叉熵在万分之几的转化率下，对「整体高一倍」不敏感。这一项的权重大小，用「AUC 下降不超过 0.01」封顶。
4. 一部分 GAID 上拟合，换一批 GAID 验收。或者 1108 拟合、1109 验收。

线上：查表 miss 就把 `gaid_cold` 置 1，4001 和 902 用请求里已经拼好的值，logit 加上对应的那个数。

8 个数如果把格子拉平了，但格子内部高分段和低分段仍一边偏高、一边偏低，再把每一格升级成两个数：

```text
logit' = a[格子] * logit_mmoe + b[格子]
```

`a` 初始为 1，`b` 初始为 0。先不要上这一步。双空格现在更像整格平移。

这张表同一格里的人分数一起动，分不出谁真会买。k=1 和 k≥32 分开报。两档要的扣分差得多，再加方案 D 或 E 的档位，不把媒体、计划直接乘进这 8 格里把表撑大。计划上的 excess 如果极不均匀，再单加「计划 × 只在双空格生效」的第二张小表，第二张用更强的正则，没有量的计划退回到那 8 个数。

## 方案 B：训练时就按线上的输入来

推迟的是**读取**，不是训练。样本到了就学；学出来的私有向量，要等它被写进的那一版上线之后，线上才读。

用两版之间的两个人说清楚。现在线上跑的是 V1。夜里的训练产出 V2，V2 上线后才替换 V1。再下一夜产出 V3。

- 甲在 V1 还在线上时第一次出现。V1 的表里没有甲，所以从出现到 V2 上线，线上都不读甲的私有向量，走方案 A 或 C。夜里生产 V2 的那次训练**会用甲当天的点击样本**，立刻更新甲的向量，写进 V2。V2 一上线就开始读甲。
- 乙在 V2 已经上线之后才第一次出现。V2 里没有乙，线上不读乙。乙的样本在生产 V3 的那次训练里学习，写进 V3。V3 上线后才读乙。

所以「下一版才新遇到的人，要到下下版才被读到」是对的。「只在下一版进行训练」不准确。甲不是等到 V2 上线之后才开始被学习，而是生产 V2 的那一次作业里就学完了。

甲的那一行在 V2 里就建出来、训好，不等到 V3。约束只在「谁的前向读这一行」：

| 日期 | 线上模型 | 甲的请求读到什么 | 这一天甲的样本进哪次训练 | 那次训练里，甲样本的主前向读什么 | 甲的那一行写到哪 |
|---|---|---|---|---|---|
| D | V1 | 没有这行，走新人路径 | 产出 V2 的那次 | 读表 V1，没有甲，走新人路径 | 写表，新建并更新，发布成 V2 |
| D+1 | V2 | 甲的向量（受方案 C 的 `n_min` 控制） | 产出 V3 的那次 | 读表 V2，有甲，读甲的向量 | 写表，继续更新，发布成 V3 |

每一行里，「线上读到什么」和「训练主前向读什么」都一样。这就是要对齐的东西。

如果把甲的初始化推到 V3，D+1 那天线上 V2 里还是没有甲，又会走一整天新人路径，双空格多高估一天。等到 V3 并不让 D+1 更一致，只是让甲多当一天新人。

V2 里这一行只有一天的样本，转化率又低，行本身可能不稳。这个担心由方案 C 的 `n_min` 管：行照常建、照常训，只是上一版里点击不够时，线上和训练都先不读它，等次数够了再用。推迟的是读，不是建。

一次训练里放两份 GAID 表：

- **读表**：上一版已经上线的那份，这次训练里冻住。前向只查它。查不到就走新人输入（方案 A 的开关，或方案 C 的共享向量）。
- **写表**：从读表拷一份出来，梯度只写这里。训练结束发布，它变成下一版的读表。

甲当天的每条样本，前向都查读表、都查不到，所以都走新人输入，用来学习新人扣分或新人向量。

甲的那一行另外做一次前向：读写表里甲的向量，主体和其他 embedding 停止梯度，用同一个购买标签，梯度只更新甲这一行。这样训出来的行，是贴着已经训好的网络学的，V2 上线读它时，网络认识这个输入。两次前向在同一个 batch 里做，只是读的表不同、更新的参数不同：

```text
主前向：slot3 = 读表[gaid]，查不到 → 新人输入；更新主体、新人参数
侧前向：slot3 = 写表[gaid]；主体停梯度，只更新写表里这一行
```一个版本内部不需要按点击顺序更新读表，因此这一步不依赖库是不是按时间排好的。它只需要一个集合：这个 GAID 在不在上一版里。

老人也读上一版的向量，不读本批样本刚刚写进去的向量。这样同一天后到的点击，不会提前用上这条样本自己的标签。

`_mask_embeddings` 那种前向置 0 会把梯度也挡住。只开这个开关、没有写表，私有向量就停在旧值，下一版没有新东西可读。读表和写表要分开。

随机丢掉一些 GAID 做 dropout 不能代替这件事。丢掉的多半是老人，老人的购买率和「第一次进表之前」不是同一分布。

验收：用读表这条前向再评双空格，cvr_diff 停在暖前向附近。评测如果仍把向量改成全 0，而线上走的是新人共享向量，两个数对不上，以线上那条为准。

## 方案 C：全 0 换成「新人共享向量」加人群

**做什么。** 全 0 不是「一个普通新人」，只是主网络没怎么见过的一个点，所以分会飘。换两样新参数：

- `e_new`：所有「表里还没有」的 GAID 共用一行，初始用现有 GAID 向量的均值，不要从 0 开始。
- `e_cohort`：按媒体、地域、设备档、小时、行业再加一组小向量。新 GAID 的输入是这两样之和。

这组参数只在冷启动前向里训练，也就是方案 B 里读表查不到的那些样本。

「慢慢混进他自己的向量」发生在**版本之间**，不是同一次请求里从共享向量动画到私有向量。每次请求只算一次用哪份向量。库如果还不能按人把点击排好，就先做两档切换，不做下面的插值。没有点击数时，`n_min` 只取 0：在上一版里就整段换上私有向量，不在就用共享向量。这和方案 B 用的是同一个集合。50、200、1000 要等次数列有了再扫。

两档：

```text
if 这个 GAID 在上一版里，并且上一版里的点击数 >= n_min:
    slot3 = e_gaid
else:
    slot3 = e_new + e_cohort
```

`n_min` 先扫 0、50、200、1000，外加一档「主前向永远不读私有行」。扫出来永远不读也能把双空格收回来，私有行就只留给老人的排序。`n_min=0` 的意思是：只要上一版写进了他，下一版请求就整段换成他的向量。这就是最粗的「混」：第一版全是共享向量，从下一版起全是他自己。

有了按时间排好的点击数之后，再换成连续比例。`n` 用上一版快照里的点击数，不参与梯度：

```text
λ = n / (n + n0)
slot3 = (1 - λ) * (e_new + e_cohort) + λ * e_gaid
```

`n0` 取 100 时：

| 上一版里的点击数 n | λ | slot3 里私有向量的占比 |
|---|---|---|
| 0（还不在表里） | 0 | 0%，全是新人向量 |
| 20 | 0.17 | 约两成 |
| 100 | 0.50 | 一半 |
| 300 | 0.75 | 四分之三 |

训练必须用同一个公式。否则网络在训练时只见过「纯新人」和「纯个人」两种向量，线上却喂一个没见过的混合向量，又会变成新的分布外点。梯度按比例走：`(1-λ)` 更新 `e_new` 和 `e_cohort`，`λ` 更新 `e_gaid`。`n=0` 时主损失不更新 `e_gaid`，他的行仍由方案 B 的写表更新，供下一版使用。

新建一行时，初值拷贝 `e_new + e_cohort`，不要填 0。这样即使 `n_min` 设小了、行被提前读到，起点仍是新人向量，而不是现在这种全 0。

人群向量要新学。工具订阅上，现有的「请求设备标识」打乱之后负样本预估会掉，说明那行现在在抬分，不能直接拿来当新人的先验。

设备标识如果比 GAID 稳（同一个人换了广告 id），冷启动可以再查一层：GAID 没有，就用这个设备上已经发布的点击、购买次数所在的档。用的是次数统计，不是旧的设备向量。标识如果只是机型，并进 `e_cohort` 就行。

**适合。** 希望新人不要全体扣同样的分。高购买人群里的新人和低购买人群里的新人，先验应该不同。双空格的平均被深点用户占着（`v4001=0` 里，当天只点 1 次的行只有 0.8%，点满 32 次的占 46.5%），一张全局扣分会偏向深点用户。

**代价。** 比方案 A 多一组参数，也要和方案 B 一起训，否则主体仍会绕开这组向量。

**算对。** 和 A 同一套冷启动指标。再加一张切片：各媒体、各地域上新人的 cvr_diff。某一档被全局均值压过头，就加大这一档人群向量的容量，而不是把所有人再扣一刀。

## 方案 D：用「已经入库的点击次数」代替 4001

细档位（第 1 次、2–3 次、4–12 次、13–31 次、32 次以上）要按 GAID 把点击按时间排一次，生成「截至上一版，这个人已经点了几次」，写成样本上的一列。这一列写好之后，训练 batch 可以继续打乱，训练循环本身不用改成按时间顺序读。

库现在不按顺序、又没有可用的时间戳时，细档位做不了。能做的只剩方案 B 那个集合特征：「这个 GAID 在不在上一版的 id 集合里」。那一比特不用排序。trace 上如果还有时间戳，离线探针可以先排 trace，不必等训练库改成有序。

有顺序时的做法：CVR 样本入库后给计数加一，小表和主模型分开发布。线上读上一版小表里的档位。模型学的是档位上所有人的购买率，不是这一个人自己的购买率。时刻 t 的特征只能包含 t 之前已经发布的点击。用当天结束时的总次数当特征，模型会记住「点满 32 次就压分」，线上第 5 次点击还在更小的档里，格子再次对不上。

点击入库只改计数，不改分数。档位权重用和主头一样的成熟购买标签来学，主体冻住，加法和方案 A 相同：`logit += b_bucket[档位]`，并且只在 `gaid_cold=1` 时加上。

L 先在有时间戳的 trace 上做两档回放：1 小时、24 小时。只有 1 小时能把 k≥4 的 excess 收回来，小表就按小时发布。24 小时已经够，就先保持「在不在上一版」这一比特。第一簇点击在小表发布前，档位是 0，仍走方案 A 或 C。

算对的标准：k≥4 的双空格比 k=1 更接近实际，k=1 的档位是 0，不被这张表额外压低。

## 方案 E：用请求次数，不用展示回传

展示次数如果靠曝光回传，会和点击回传一样晚到，不适合当这只 bug 的计数。改成**请求次数**：请求进入打分逻辑时，就给这个 GAID 加一，发生在任何展示回传、点击回传之前。

本次请求用的数，是这次进来之前的累计，档位可以先用 0、1–5、6–20、21+。多机各自计数会漏，先打成档位就够用；要更准再放一个共享计数。这一步不读训练库，所以库不按顺序也不影响线上计数。

训练不能事后在无序库里重算这个数，否则又和线上不一致。把当时参与打分的档位打进样本，训练只读这一列。样本里还没有这一列之前，E 的权重先不上，新人仍用方案 A。库里如果其实有请求时间戳、只是没排序，就和方案 D 一样：按 GAID 加时间排一次，生成档位列，然后再打乱训练。

档位加在 logit 上，只在 `gaid_cold=1` 且 4001、902 为空时生效，主体冻住：

```text
logit += b_req[请求档]
```

学出来若是「请求越多分越高」，这张表不上。请求多只说明这个 id 来过很多次，购买率不一定更低，所以先限制在点击特征仍为空的新人上，并用留出的 GAID 看分档曲线。

算对的标准和方案 D 相同：高档比 0 档更接近实际，0 档保持方案 A 或 C 的水平。

## 方案 F：两个网络，共享 embedding，新人网络不吃 GAID

这个做法可行。共享的是 embedding 表，两套网络的权重分开。同一次请求只走其中一个。

```text
共享表：广告、上下文、4001、902 以及其他非 GAID 槽位
GAID 表：只接老人网络

if 这个 GAID 在上一版表里:
    logit = Net_warm(全部 embedding，含 GAID)
else:
    logit = Net_cold(除 GAID 以外的 embedding)
```

同一套 MMoE 权重、只是把 GAID 拿掉或置 0，就是现在的 mask 实验，双空格会回到 +102%。所以新人必须是另一套权重，不能只在老人网络上做特征消融。

新人网络要留下 4001 和 902，包括它们的空值。绿带里广告特征拿掉之后预估下降大约 40%，说明广告向量在抬分。新人网络如果把用户侧特征一并拿掉、只剩广告和上下文，分会更高。拿掉的只有 GAID 这一路 id。空着的 4001、902 本身就是「现在没有点击负反馈」的输入，让 Net_cold 自己学这个输入，或者仍叠方案 A 的 8 个数。

训练顺序：

1. Net_warm 用现在的模型，先冻住，包含共享 embedding。
2. Net_cold 从 Net_warm 拷贝除 GAID 以外的权重，作为初值。这一步刚拷完，输出会接近 mask 的 +102%，这是起点，不是结果。
3. 只用新人样本微调 Net_cold：GAID 不在上一版里的人，或者按方案 B 读表查不到的那些样本。购买标签。梯度先不写回共享 embedding。
4. 这一步能把双空格收回来，说明现有 embedding 够用，缺的是「没有 GAID 时上面那层网络」。收不回来，再给 Net_cold 加一层自己的小投影，只训这层，仍然先不动共享表。共享表最后要不要对新人放开梯度，看这层投影还够不够。

不要用全量老人、只是把 GAID 列丢掉，来训 Net_cold。那样学到的是「老人去掉 id 之后的平均购买率」。双空新人比这个平均更差，分还会偏高。

GAID 行如果被点击头和购买头共用，点击梯度会把深点用户往「爱点」推。Net_cold 不接这行，购买修正也不会写回这行，两边就不再抢。

方案 A 是这个结构的特例：Net_cold 退化成「老人 logit 加 8 个数」。A 的留出评估收不住，再上完整的 Net_cold。Net_cold 相对 A 的提升，要在留出的计划和留出的 GAID 上出现，避免小网络只记住了几个大计划。AUC 下降仍不超过 0.01。

## 方案 G：把老人 GAID 向量的压分，蒸馏到上下文上

先做一张诊断，再决定要不要训这个小模型。用「GAID 行在评估日之前就已经发布」的老人，不要用 8e8 那种当天刚写进向量的人。例如 checkpoint 是 1107/23，人是 1107 已经出现、1108 又来的那些。对每个人算两次前向，大模型冻住：

```text
delta = logit(带上他的 GAID 向量) − logit(GAID 按线上新人那样处理)
```

按媒体、再按头部计划，算 `ln(Σ p_warm / Σ p_cold)`，也就是这一档要扣多少 logit，概率口径（原因见下面的监督函数）。各媒体差不多，说明压分没有上下文差别，方案 A 的一个格子就够，G 不必做。某个媒体大约 −0.2、另一个大约 −1.5，G 才有东西可学。

小模型 `g` 的输入和输出：

- 输入：媒体、计划（量大的才单独留，其余并进媒体）、素材档、设备档、地域、小时、行业、4001 是否为空、902 是否为空。不放 GAID。
- 输出：一个数，加在新人路径的 logit 上。
- 先用 FTRL 的线性模型。线性模型在留出的媒体上不够，再换成小 MLP。计划向媒体收缩，避免记住个别计划。

监督不直接回归 `delta`，而是在概率上对齐老人网络。老师是带 GAID 的预估，学生是新人路径加上 `g`：

```text
z_warm = logit(带上他的 GAID 向量)          # 停止梯度
z_cold = logit(GAID 按线上新人那样处理)       # 停止梯度
p_warm = sigmoid(z_warm)
p      = sigmoid(z_cold + g(x))

L = Σ_i w_i · [ −p_warm,i · log p_i − (1 − p_warm,i) · log(1 − p_i) ] + 正则
```

这是以 `p_warm` 为软标签的交叉熵。`w_i` 用和评估一样的样本权重。对 `g` 的梯度是 `w_i · (p_i − p_warm,i)`。训到收敛时，同一档上下文里 `Σ p = Σ p_warm`：新人路径加上 `g` 之后，这一档的平均预估等于老人带着向量时的平均预估。cvr_diff 量的就是这个平均，所以对齐在同一个口径上。

回归 `delta`（平方损失或 Huber）会多扣分。平方损失学到的是 `delta` 的均值，而概率要对齐的是 `log 平均(e^delta)`。只要同一档里的人 `delta` 不一样，前者就比后者更负。例子：同一档两个人，新人路径都打 0.001，`delta` 一个 −0.2、一个 −2.0。

| | 数值 |
|---|---|
| 老人网络的两个预估 | 0.00082、0.00014，平均 0.00048 |
| 概率对齐要的 `g` | ln(0.48) ≈ −0.74 |
| 平方损失学到的 `g` | 两个 `delta` 的均值 −1.1 |
| 用 −1.1 之后的预估 | 0.00033，比老人平均低大约三成 |

Huber 介于均值和中位数之间，同样不对齐平均概率。

上面的 `g` 是在老人身上学的，老人和新人的购买率不一定一样。所以按这个顺序：

1. 在老人上用上面的 `L` 训 `g`，训完冻住。
2. 再在新人身上，用真实购买标签拟合方案 A 的 8 个数，加在 `z_cold + g(x)` 之后。老人和新人整体水平的差，由这 8 个数收掉。

线上只在 GAID 不在表里时使用，避免和真的 GAID 向量叠两次：

```text
logit = logit(新人路径) + g(x) + b_A[格子]
```

新人路径是方案 F 的 Net_cold，或者还没做 F 时的「老人网络 + GAID 置 0」。`g` 管同一档新人内部按上下文的差别，A 的 8 个数管新人整体水平。A 是在 `g` 之后拟合的，同一截压分不会加两次。

`g` 学得到的是「这类流量上，GAID 向量通常减多少」。同一种流量里某个人特别能点、特别不买，`g` 看不到，这部分仍等方案 B 的下一版私有向量。

验收看留出的新 GAID 的 cvr_diff，不看 `L` 训得多低。`L` 低只说明 `g` 学会了老人身上的差，不说明新人被校准了。

## 怎么搭

六种搭法，按手上的数据条件选，不必六套一起上。

1. **只想先压住高一倍，改动最小。** 方案 A。线上 miss 时加一档 logit。同时用留出的人看 k=1 和 k≥32，决定要不要往下走。
2. **希望训练和线上以后对齐。** 方案 B + 方案 A。B 负责「前向看见的输入和线上一样」，A 负责这一格的水平。
3. **希望新人之间有差别。** 把搭法 2 里的 A 换成方案 C。设备 id 能对上「换了 GAID」的人，再加一层设备次数回退。
4. **点击样本大约一小时内能入库。** 搭法 2 或 3，加上方案 D。0 档仍用 A/C，后面的档用已发布次数。
5. **点击样本要等一天，第一天就要区分深点用户。** 用方案 E 的请求次数代替方案 D。请求在进模型时计数，不靠展示回传。档位打进样本之后再训权重。
6. **一张表拟合不好，而且偏差跟着计划、素材变。** 在搭法 2 上加方案 F 或方案 G。先看 excess 按计划的分布：集中就扩 A 的键，铺平再加头。

不管哪一搭，验收都看**和线上相同的那条输入**，并保留一条暖前向做对照。暖前向选「eval 当天没有进训练」的日子。8e8 同日的 +12% 是上界。

要先量的三个数，决定用 4 还是 5：

- 线上请求里，GAID 不在表里的占比（方案 B 的掩码比例跟它走）
- 点击发生到 CVR 样本可见，要多久（短则 D，长则 E）
- 点击发生到 4001/902 可见，要多久（用来解释现在为什么空，不决定方案）

## 先别做的

- 点击一到就给 GAID 行打负梯度。购买结果还没有，会把后来会买的人一起打下去。
- 随机 dropout GAID 向量。丢掉的是老人，填不满新人前缀的分布。
- 用单个 GAID 的购买率当第一天的主修正。几十次点击移不动带先验的收缩估计。
- 扣分表和主体、GAID 行一起训，指望表自己留在 logit 上。
- 用 8e8 当天的 +11.9% 当新人目标。

## 和现有实验的关系

方案 A 的基线就是现在的 mask 评测。四宫格里除了双空，`4001=0 且 902 非空` 在 mask 下仍有 **+37.5%**，`4001 非空且 902=0` 从 +16% 到 **+58%**。表的键要把这两格包括进去，不单做双空。

工具订阅那篇里，请求与设备打乱后负样本预估上升大约 20%，和「拿掉 GAID 行，分数升高」是同一个方向。那篇看的是老人身上谁在抬分；这篇看的是这行向量线上不存在时分落在哪里。正在跑的置零追训可以继续，它和冷启动前缀不是同一分布。
