# GAID 线上线下不一致：冷启动训练与 serving 方案

日期：2026-11-24。输入是同目录之外的评测纪要《GAID 空初始化与实时点击特征滞后》，数字都来自那里，这里不重跑。那篇把现象定死了：双空格（`4001=0` 且 `902=0`）在 7e8 上 cvr_diff **+101.8%**，占正 excess 的 **70.7%**；同一天 trace 换上 8e8 后降到 **+11.9%**；把 8e8 的 `req_gaid`（slot 3）置 0 又回到 **+101.5%**。全局从 +76.4% 到 +11.5%，mask 之后回到 +70.3%。

要解决的是两件事。

1. 离线前向读的是正在被本窗口样本更新的 GAID embedding，线上没见过的 GAID 是零向量。零向量把双空格打回 +102%。
2. 负反馈现在只走「GAID 行记住这批点击没转化」。点击样本是 CVR 样本，转化标签还有归因延迟，请求时也拿不到「这个 GAID 刚刚产生了点击样本」。4001 / 902 本应承担这件负反馈，但 `v4001=0` 的 93.2% 不是当天第一点，46.5% 的行来自当天点击不少于 32 次的 GAID。

新 GAID 的训练和 serving 用同一套路由。目标是让「线上还没有这行 embedding」变成训练里的一条正式路径，而不是把零向量交给主网络外推。

## 1. 验收口径先改

8e8 在 1108 trace 上的 +11.9% 是这批 GAID 已经进入 `20261108/23` 训练之后的数。它证明 GAID 行有能力把这批人的分数拉下来，也证明这股拉力几乎全部住在 slot 3：mask 之后双空格回到 +101.5%，和 7e8 没见过这些人时一样。

线上新 GAID 走的是 mask 那一列，不是 8e8 基线那一列。后面所有方案的主指标都定义在 **serving 对齐前向** 上：

- 模型发布时点是 T。请求时间 t 能用的 GAID 状态，只包括发布时间 ≤ t − δ 的快照。δ 是这版快照真正被加载的延迟。
- 该 GAID 第一次进入快照之前的请求，全部走冷启动路径。
- 主指标是这条路径上的双空格 cvr_diff、四宫格、以及 k 桶（当天第几次点击）。对照是同一天、同一 checkpoint 的暖 GAID 前向。
- 暖前向在「eval 日没有进入训练」的日子上再报一列。8e8 那种同日 in-sample 只作为上界：它告诉你 GAID 行最多能收回多少，不作为上线目标。

成功标准，三个一起看：

- 双空格在冷启动前向上的 cvr_diff，落到暖前向的 ±10 个点以内。暖前向自身还留着大约 +12% 的全局水平，那是另一件事；这篇要收回的是 mask 造成的那约 90 个点（101.5 − 11.9）。
- 工具订阅 AUC 相对暖前向下降不超过 0.01。k=1 和 k≥4 分开报，避免只把深点用户压下去、或者只加一个常数把第一点一起压坏。
- 普货、VSL 的 AUC 和 cvr_diff 留在评估噪声里。GAID 行如果是多行业共用的，冷启动参数按行业分开。

logit 量级先心算一下，正式拟合时用格子里的样本重算。双空格 pcvr / acvr ≈ 2.02。转化率远小于 1 时，这大约是 **0.7 的 logit**。行业一维偏置那次，和主体一起训，需要的量级被抵消到 +0.03。冷启动修正如果和 GAID 行、主体网络一起更新，会再碰到同一种抵消。

## 2. 请求时实际上有什么

按「标签」和「特征」分开，不然容易把点击当成 CVR 负样本。

| 信号 | 请求时 | 说明 |
|---|---|---|
| GAID 是否在已发布的表里 | 有 | 查表 miss 就是现在的置空 |
| 4001、902、clk、wups | 经常是空的 | 空的 fid 把「真没点过」和「点过但没拼上」写成同一个值。4001=0 的 fid 是 `17187942447025` |
| 这次请求本身、bidder 侧的展示次数 | 有 | 不经过点击样本。深点用户的展示次数只会更多 |
| 点击样本到没到 | 没有保证 | 用户给的约束。不能假设点击回传能在同一簇点击里写进特征 |
| 点击事件 | 即使看到了，也不是 CVR 负标签 | CVR 的负样本是「点击且归因窗口内没有转化」。在点击瞬间做一次负梯度，会把晚转化的人一起打下去 |
| 成熟的 CVR 标签 | 只在训练管道里，按现有归因窗口 | 冷启动参数用和主头一样的标签，不另造一套更短的负样本 |

因此负反馈分成两种，都不要实时点击标签：

- **跨用户的格子偏置**。`(冷启动状态, 已发布的点击桶, 4001/902 是否为空)` 上的转化率，用大量用户的成熟标签估计。一个桶里有足够的正样本，低转化率下也能估计水平。单个 GAID 的后验则不行。
- **下一版才读的个体状态**。这一个 GAID 的行或计数，继续用点击样本更新，但本版前向不读它。这就是 8e8 已经证明有用的那股力，推迟到线上真的加载得到的时候再生效。

低转化率下，单个 GAID 的经验转化率在几十次点击里几乎离不开先验。工具订阅整体实际转化率大约是 0.035%（敏感性那篇，11 月 8 日）；双空格自己的绝对转化率纪要里没有。即便按这个整体水平的几倍来估，32 次点击、0 次转化也移不动一个带先验的收缩估计。8e8 能把双空格拉下来，是因为这行高维参数在同一天的负样本上被连续更新，而且评估时这行已经可见。这个数留作个体修正的上界，放进下一版快照。新 GAID 第一天的水平用格子估计。`v4001=0` 有 42.8 万行，双空大约占其中 17%，格子水平估得准。

## 3. 方案

五件事叠在一条路由上，按这个顺序做。3.1 的两档延迟只用现有 trace 就能判断要不要后面的基建。

### 3.1 冻住主体，用点时刻的 k 做格子偏置

这是探针，也是后面校准头的雏形。

做法：主体和现有 embedding 全部冻住。在 logit 上加一张小表，键是

`(gaid_cold, bucket(k_visible), empty_4001, empty_902)`

`gaid_cold` 在这步先直接用现成的 mask：slot 3 置 0，和线上一致。`k_visible` 用 trace 里的时间戳重建，规则是「时间 < t − L 的点击次数」，不要用当天总次数 n。L 做两档：1 小时和 24 小时。分桶沿用那篇里已经切开的 k：1、2–3、4–12、13–31、≥32。空特征用 trace 里的 `v4001`、`n902`。

表用 FTRL，只更新这张表。损失是 CVR 交叉熵，另加一项桶内均值对齐：每个桶的平均预估对齐平均标签，权重用「AUC 下降不超过 0.01」封顶。交叉熵在这种转化率下对水平不敏感，均值项是专门收 cvr_diff 的。

拟合和验收拆开。在一部分 GAID 上拟合，在没见过的 GAID 上验收；或者在 1108 拟合，在 1109 验收。同一天的点击既当特征又当标签，会把探针做成另一个 8e8。

读法：

- L=24 小时、也就是整天的第一版快照都还没有这个人时，双空格已经落到暖前向附近：线上只需要「查表 miss」这个比特，加上一张冷启动偏置。深点用户的残余留给后面的计数特征，不阻塞这一步上线。
- 只有 L=1 小时能把 k≥4 的 excess 收掉：负反馈主要在「上一小时的点击已经可见」之后，值得做小时级计数，仍然不需要实时点击。
- 两档都不动：偏置被键切碎了，或者双空格内部方向不一致。先看下面的切片再改结构。
- k=1 和 k≥32 分开报。两档要的修正差得多的话，一张不带 k 的常数就不够。纪要里浅层 `n≤10 × k=1–3` 和深层 `n≥32 × k=4–31` 都贡献 excess，但没有按 k 给 cvr_diff，这一刀要这次探针自己出。

同时出一张诊断，决定 3.4 要不要做：冷启动且双空的 excess，按媒体和广告计划累计。集中在少数计划上，就加「计划 × 冷启动」这一维，不必上风险模型。铺得很平，格子偏置就是最终形态，风险头没有可拟合的残差。

这一步的 serving 改动只有一处：mask 路径的 logit 加上 `b[1, k=0, empty, empty]`。k 先按 0，因为还没有计数。

### 3.2 前向只读上一版快照，冷启动不再喂零向量

3.1 如果在 mask 路径上能校准，就把它从「评估时置零」收成训练和线上的同一条路由。继续只在评估时 mask，主体会在下一次全量训练里把这张表抵消掉。

每个 GAID 维护两样东西，发布时间相同：

- 高维行 `e_g`，也就是现在的 slot 3。
- 计数 `(n_s, c_s)`：这版快照覆盖到的点击数和成熟转化数。

请求时：

```text
n = n_s(gaid)          # 没有这行则为 0
if n >= n_min:
    user = shrink(e_g, e_cohort, n)
else:
    user = e_cohort(cohort)
logit = mmoe(user, ad, context, ups) + b[cold=(n<n_min), bucket(n), ups_empty]
```

`shrink` 用 `λ(n) = n / (n + n0)`，`user = (1-λ) e_cohort + λ e_g`。`n` 只用快照里的 n，不用样本里能看到的当天总点击。`n0` 和 `n_min` 在 3.1 的回放上扫。低转化率下 `n_min` 的候选是「这行根本不进主前向」、50、200、1000。扫出来主前向完全不读 `e_g` 也能收住双空格，那这只 bug 就是格子水平，高维行只留给暖用户的排序。尾部用户还偏，再把 `n_min` 降到那一档。

`e_cohort` 是一组新参数，输入是请求里本来就有的粗上下文：媒体、地域、设备档、小时、行业。它在冷启动前向里被训练，用来给新 GAID 一个人群先验。不要复用现在的「请求设备标识」embedding。那组特征在工具订阅上打乱之后负样本预估下降，说明现有设备行在抬分；冷启动人群向量要在冷启动前向里重新学。

零向量从主网络的输入里拿掉。线上查表 miss 时送 `e_cohort`，不送 0。`e_cohort` 的初始值用暖 GAID 行的均值，避免它自己又从 0 开始被主网络外推。

训练窗口里的一条样本，走和线上相同的判断。GAID 第一次被某版快照覆盖之前，`n=0`，走 `e_cohort`。梯度进 `e_cohort` 和偏置表，不进这个 GAID 的高维行。高维行用一条侧向损失更新：主体停梯度，只把梯度送进 `e_g`，供下一版快照使用。这样第一天的点击仍然会把这行训出来，第二天的暖路径还能拿到 8e8 那种个体修正；同一天的前向不会读到它。

现有的 `_mask_embeddings` 是前向置 0，梯度到不了这行。训练里如果直接开这支 mask，GAID 行会停更，暖路径的收益一起没了。冷启动前向和侧向更新要分成两支。

`n_min` 以下的样本只更新人群和格子，不更新高维行在主损失里的用法。新 GAID 的训练信号因此是密的：所有新人共享 `e_cohort` 和 `b_cold`，而不是各自写进一个线上还不会读的私有行。

### 3.3 快照计数代替 4001，作为负反馈特征

4001 空着的时候，模型缺的是「已经点了很多次」。这个数可以从 CVR 样本管道里得到，不必从 UPS 回传，也不必在点击瞬间拿到。

小时任务在产出训练样本时，顺手把每个 GAID 的 `(n, c)` 写成一张小表，和主 checkpoint 分开发布。线上查这张表。表的延迟等于样本入库加发布，不等于 4001 那条链路。纪要里的判断是 4001 比模型更新更慢，所以这张表可以比 4001 先可见。

主网络看到的是桶 id，不是这个人的经验转化率。桶内转化率由 3.1 的偏置在大量用户上估计。一个新 GAID 的第 1 到第 3 次已发布点击，用的是历史上所有人在这个桶里的水平。个体后验只在 `n≥n_min` 之后以收缩的形式加进来。

点时刻对齐是这张表的合同。训练特征是 `n_s(t−δ)`，评估也是。用当天结束时的 n 做特征，模型会记住「n≥32 则压分」，但线上在第 5 次点击时只能看到一个更小的桶，格子又会错位。这和现在「训练读到了行、线上是 0」是同一种错，只是从 embedding 换到了计数。

L=24 小时的探针已经够用时，这张表照样要建，键先只用「是否已进入任一版快照」。等样本延迟降下来，更细的 k 桶自动生效，模型不用改结构。

点击瞬间只允许加计数，不允许加负梯度。计数的权重来自成熟标签。转化窗口和主头保持一致。

### 3.4 新 GAID 内部的区分：人群、设备回退、上下文风险

冷启动路径上的平均水平由 3.1 和 3.2 负责。新用户之间的差别用三层，都不用实时点击。

**人群向量**已经在 3.2 里。它让高转化人群里的新 GAID 和低转化人群用不同的先验，避免一张全局负偏置把所有新人压到双空格的总均值。双空格的总均值被深点用户占着（`v4001=0` 里 n=1 的行只占 0.8%，n≥32 占 46.5%），全局常数会偏向深点用户。人群向量是把这个均值拆开的第一刀。

**设备标识上的快照统计**。新 GAID 有一部分是同一设备换了广告 id。请求里如果已经有比 GAID 更稳定的设备标识，冷启动查表的顺序是：GAID 快照，没有则设备标识的 `(n, c)` 桶，再没有才是纯人群。用的是设备上的结果统计，不是现有的设备 embedding。设备标识的基数如果只是机型，就并进人群，不单独建表。

**上下文风险头，只在诊断说 excess 集中时再加。** 标签用窗口结束才知道的结果：这个 GAID 在窗口内点击深、且转化为 0。特征只有请求上下文（媒体、计划、设备档、地域、小时、行业），明确不放 GAID，不放 4001/902。线上在 `n=0` 时输出一个 logit 修正。它学的是「哪类流量会冒出这批人」，不是「这个人已经点了很多次」。3.1 的计划切片如果是平的，这一头没有增量，不做。

三层都在冷启动前向里训练。暖 GAID 不走这里，避免用老用户的转化率去填新人的先验。不要对 GAID 做随机 dropout：随机丢掉的是暖用户，他们的标签分布和「第一次进表之前」不一样，冷启动偏置会被暖用户的均值带偏。掩码只打在每个 GAID 真实的前缀上，比例由线上新 GAID 的请求占比决定，先去量这个占比。

### 3.5 主体里的冷启动专家，放到最后

MMoE 上可以加一个只吃冷启动路由的专家，门控特征是 `n<n_min`。它解决的是「格子偏置的形状不够」，也就是 3.1 两档 L 都收不住、而且残差随广告特征强烈弯曲的情况。

专家的训练样本必须是冷启动前向。门控在训练里几乎不打开的话，线上打开就是一条没训过的支路。在 3.1–3.4 没做完之前，看不出这个专家和一张更细的偏置表哪个更合适。偏置表能收住，就不要加专家。

## 4. 新 GAID 的训练和 serving

把第 3 节收成一条路径。

**一次请求**

1. 取最近一个已加载快照里这个 GAID 的 `n`、`e_g`。没有则 `n=0`。
2. `n≥n_min`：用户向量用收缩后的 `e_g`。这是第二天及以后的路径，个体修正在这里生效。
3. `n<n_min` 且设备标识有快照计数：用户向量用 `e_cohort`，桶用设备计数和 GAID 计数里已发布的那个。
4. 否则：用户向量用 `e_cohort`，桶用本 GAID 已发布的点击数，第一次请求就是 0 桶。
5. logit 加 `b[cold, bucket, ups_empty, industry]`。4001、902 原样进主网络，另加一个 `ups_age`：特征生成时间到请求时间的桶。年龄大且 4001=0，走「未知」偏置；年龄小且 4001=0，才是「确实没点过」。现在这两种共用 fid `17187942447025`，模型无法把负反馈只加在滞后上。
6. 落日志：`n_s`、`cold`、`ups_age`、用了哪一级回退。下一次训练按这四项重放。在日志落地之前，用 trace 时间戳按第 3.1 节重建，作为过渡。

**一次训练**

1. 样本按时间和模拟的发布边界回放，主损失只走上面的路由。
2. `e_cohort`、格子偏置、`ups_age` 的参数由冷启动样本更新。新 GAID 的梯度集中在这些共享参数上。
3. `e_g` 只吃侧向、主体停梯度的更新，写入下一版快照。主损失在 `n≥n_min` 的后续请求里才读它。
4. 核对 GAID 行是不是点击头和购买头共用。如果共用，深点用户的点击梯度会把这行推向「爱点」，和购买头要的修正相反。冷启动偏置写在购买 logit 上，不回写共用的 GAID 行。个体行的侧向损失也只用购买标签。
5. 发布两份产物：主模型（含 `e_cohort` 和偏置），以及比主模型更小的 `(gaid → n, c, e_g)` 快照。计数表可以比完整 MMoE 更频繁地换，因为它只依赖样本聚合。

新用户因此有三段，而不是「第一天全是 0，第二天突然换成一个记满当天负样本的高维行」：

| 阶段 | 线上读什么 | 谁在学习 |
|---|---|---|
| 第一次进任一快照之前 | `e_cohort` + 0 桶偏置 | 历史上所有新人的成熟标签，共享参数 |
| 已有计数，未到 `n_min` | `e_cohort` + 点击桶偏置 | 同桶用户的标签；这行 GAID 只在侧向里预热 |
| `n≥n_min` | 收缩后的 `e_g` | 主损失开始读这行，个体修正叠在人群之上 |

第一段覆盖真正的第一点（k=1 占 `v4001=0` 的 6.8%）。第二段覆盖「点了很多次、4001 仍是 0」的主体（k≥2 占 93.2%），条件是两档 L 的探针证明较小的 L 有增量。第三段保留现在 8e8 已经看到的个体能力，同时用 `n0` 限制单日负样本把行推离人群太远。

## 5. 和现有实验怎么接

探针直接复用 mask 评测和已有的 k、n 重建，不改训练管道就能做完 3.1。

| 已有产物 | 用来做什么 |
|---|---|
| `mask_groups=req_gaid` | 冷启动前向的现状基线。新方案上线后，同一开关换成「走 `e_cohort`」，不应再回到 +102% |
| 四宫格 `pdf_4001_902_2x2` | 主指标。双空格是第一格，`4001=0,902≠0` 在 mask 下仍有 +37.5%，路由不能只覆盖双空 |
| `pdf_v4001_0_n_k_dist_1108` 的时间戳 | 重建 `k_visible`。验收按 k 桶拆 cvr_diff，分布那张表只有行数 |
| 绿带 shuffle | 预期：adps / clk / sess / wups 仍是暖用户上的排序特征。冷启动修正上线后，再 shuffle 这几组，双空格的水平不应再主要靠它们 |

`4001≠0, 902=0` 那格样本少，mask 之后 cvr_diff 从 +16.2% 到 +58.2%，方向和双空一样，都是 GAID 行在压分。同一张 `gaid_cold` 表会覆盖到它，不单独做。

工具订阅那篇里，请求与设备打乱后负样本预估上升大约 20%，和「去掉 GAID 行，分数升高」是同一个方向。那篇要回答的是暖用户上哪些特征在抬整体水平；这篇要回答的是这些特征里的 GAID 行在线上不存在时，分数落在哪里。置零追训继续跑可以，它回答不了冷启动路径，因为训练时被置零的样本和「这个 GAID 第二天又有了行」不是同一分布。

## 6. 不做的做法

- 把线上也改成实时训 GAID 行。第一簇点击里行不稳定，纪要已经写了；转化标签在点击瞬间也不存在，实时梯度没有 CVR 负样本可用。
- 全局随机丢掉 GAID 行做 dropout。丢掉的暖用户带不来新人的标签分布。
- 用单个 GAID 的 Beta 后验当主修正。在这个转化率下，几十次点击移不动带先验的收缩估计。8e8 的降幅来自高维行见过当天标签，放到下一版快照里用，不拿来代替第一天的格子水平。
- 把点击事件直接当成一次负反馈写进 GAID 行。那是在惩罚所有点击，包括会转化的点击。
- 冷启动偏置和主体、GAID 行联合训练，指望它自己留在 logit 上。行业偏置那次留不住。
- 用 8e8 同日双空格 +11.9% 当作线上新 GAID 的目标。那一列的 GAID 行见过当天的标签。

## 7. 建议的落地顺序

1. 量三个数：线上新 GAID 的请求占比、点击发生到 CVR 样本可见的延迟、点击发生到 4001/902 可见的延迟。第 3 节的分支取决于前两个数，第三个用来解释现状。
2. 做 3.1 的冻住探针，L=1 小时和 L=24 小时，GAID 留出一截验收。出 k 桶和计划切片。
3. 探针能收住双空格，就按 3.2 改训练路由和 serving：miss 走 `e_cohort`，主前向不读零向量，高维行走侧向。`n_min` 用探针扫。
4. L=1 小时明显好于 L=24 小时，再上 3.3 的计数快照。否则计数表只保留「是否进过快照」一个比特。
5. 计划切片集中，再加「计划 × 冷启动」。设备标识能对上「换 GAID」，再加设备回退。两张切片都平，就停在人群向量加格子偏置。
6. 每一步都用第 1 节的冷启动前向报数，并保留暖前向。mask 评测从「置 0」改成「走即将上线的那条路由」之后，双空格 cvr_diff 应停在暖前向附近，而不是回到 +102%。
