# GAID 新人高估：几套可以分开做的模型方案

日期：2026-11-24。数字来自评测纪要《GAID 空初始化与实时点击特征滞后》，这里不重跑。

## 这件事在说什么

模型给「这个人会不会买」打分时，很依赖两样东西：

1. **这个 GAID 自己的一串向量**（slot 3，`req_gaid`）。老人点了很多次却很少买，这串向量会把他的分往下拉。
2. **最近点了多少次**（4001 的 24 小时点击、902 的 session）。绿带实验里，这类点击统计本来就是压分、拉排序的主力。

线上两类人经常两样都没有：

- GAID 没进已发布的表，向量被填成 **全 0**。
- 点击其实已经发生了，4001 / 902 仍是 0。`v4001=0` 的行里，**93% 不是当天第一下**，**将近一半**来自当天点了 32 次以上的人。

结果就是双空格（4001 和 902 都是 0）预估比实际高大约 **一倍**（cvr_diff **+102%**），并且占了正 excess 的 **七成**。

有一个对照把原因钉死了：同一批人，等当天样本训进模型（8e8），双空格只剩 **+12%**；再把这版模型的 GAID 向量人为改成 0，又回到 **+102%**。分是被 GAID 那一行拉下来的。线上新人走的就是「向量为 0」这条，不是「已经训过」那条。

8e8 的 +12% 不能当成新人上线后的效果。那一版模型在评估当天已经见过这些人的购买标签。它只说明：这行向量**有能力**记住这批人。线上要等下一版发布才读得到。

转化率很低（工具订阅整体大约 0.035%）。一个人点几十次、一次没买，并不足以单独证明他比平均更差。1108 当天 `v4001=0` 有 42.8 万行，双空大约占其中 17%，**这一格的平均水平**估得准。所以新人第一天靠格子，一个人自己的向量留到下一版再用。

还有一条约束：样本是点击之后的 CVR。点击发生的那一下，购买结果还没出来，**这一下本身不是负样本**。请求时也经常不知道「点击样本生成了没有」。方案里凡是写「负反馈」的，都是下面两种之一：很多用户共享的一档分数，或者等样本入库之后、下一版才生效的个人统计。不在点击瞬间给 GAID 记一笔负分。

## 方案一览

| 方案 | 一句话 | 要不要新基建 | 新人之间有没有差别 |
|---|---|---|---|
| A. 新人扣分表 | 向量为 0 时，logit 上按格子减一截 | 不用，先离线就能验 | 只有格子那么粗 |
| B. 训练按线上来 | 训练时，还没发布的 GAID 不用他的私有向量 | 改训练，serving 换掉全 0 | 取决于下面叠哪张表 |
| C. 新人共享向量 | 全 0 换成学出来的默认向量，再加人群 | 改训练和查表 | 有，按媒体、地域、设备档、小时 |
| D. 已发布点击次数 | 用样本管道里的次数代替迟到的 4001 | 一张小计数表 | 有，按点了几次 |
| E. 展示次数 | 竞价自己数看了几次，不看点击样本 | bidder 侧计数 | 有，按展示档 |
| F. 新人小网络 | 老人走原模型，新人走另一个小头 | 多一个头 | 有，靠上下文 |
| G. 把老人的压分蒸馏出来 | 用上下文去预测「若有 GAID 向量会减多少分」 | 多一个小头 | 有，靠上下文 |

A 到 E 是主体。F、G 是 A 不够用时的加项。B 是训练合同，建议和其中一张表一起做，否则下一次全量训练会把单独加的表抵消掉。行业一维偏置那次，和主体一起训，修正被挤到大约 +0.03，就是这个现象。双空格这一格大约差 **0.7 的 logit**（预估是实际的 2 倍，转化率又很低），量级大，更要冻住主体来拟合，或者让主体在训练时就看见和线上一样的输入。

下面每套都写：做什么、适合什么、代价、做成什么样算对。

## 方案 A：新人扣分表

**做什么。** 大模型全部冻住，包括现有 GAID 向量。只在最后的 logit 上加一张小表，用 FTRL 更新。键用请求时真的有的信息：

- GAID 向量是不是 0（离线用现成的 `mask_groups=req_gaid` 模拟）
- 4001 是不是 0，902 是不是空
- 可选：媒体、广告计划、行业

损失用原来的 CVR 交叉熵，再加一项「这一格的平均预估对齐平均实际」。交叉熵在万分之几的转化率下对「整体偏高一倍」不敏感，均值项就是专门收 cvr_diff 的。均值项的权重大小，用「AUC 掉不超过 0.01」封顶。

拟合和验收用不同的人：一部分 GAID 上拟合，留出的 GAID 上看；或者 1108 拟合、1109 验收。同一批点击既当特征又当答案，会把这张表做成另一个 8e8。

**适合。** 先确认「高一倍」是不是这一格的平均水平问题。也是改动最小、可以先上的一版：线上查表 miss 时，logit 加上 `b(向量为 0, 4001 空, 902 空)`。

**代价。** 同一格里的新人分数一起动。真会买的新人和乱点的新人，在这一步分不开。k=1 和 k≥32 要分开报。纪要里浅层和深层都有 excess，但没给各档的 cvr_diff，得这张表自己出。两档要的扣分差得多，就在表上加「第几次」或换成方案 D / E，不继续加厚这张常数表。

**算对。** 留出的人里，双空格 cvr_diff 落到暖前向（GAID 向量还在）的 ±10 个点以内。工具订阅 AUC 下降不超过 0.01。普货、VSL 基本不动。

## 方案 B：训练时就按线上的输入来

**做什么。** 现在的错位是：训练样本里这个 GAID 一定在，梯度会更新他的向量，前向读的就是这行正在变的向量；线上他不在表里，读到的是 0。

改成按发布时间回放。请求时刻 t 只能用「已经加载的那一版」里的向量。这个人第一次被某一版覆盖之前，前向不读他的私有行。梯度进共享的默认参数（方案 C）或扣分表（方案 A）。私有行另外用一条侧向损失更新：大网络停梯度，只更新这一行，写进**下一版**。这样：

- 今天的前向和线上一致，模型学的是「还没有这个人」时该出多少分。
- 明天发布之后，这行向量仍然在，8e8 那种个人修正还在，只是晚一版。

现有的 `_mask_embeddings` 是前向直接置 0，梯度到不了这一行。训练里如果把这个开关打开就完事，个人向量会停更，第二天的收益也没了。冷启动前向和侧向更新要分成两支。

掩码打在每个人**真实的前缀**上（第一次发布之前的那些样本），比例跟线上新 GAID 的请求占比走。随机丢掉一些 GAID 不行：丢掉的多半是老人，老人的购买率和新人的前缀不是一回事，扣分表会被老人的均值带偏。

**适合。** 作为训练合同，和 A 或 C 一起做。只在评估时 mask、训练仍读私有向量，下一次全量训练会把 A 的表抵消掉。

**代价。** 要改样本回放，按发布边界决定这条样本读不读私有行。serving 上「查表 miss」要和训练用同一个默认输入。

**算对。** 用「走这套默认输入」再评一次双空格，cvr_diff 停在暖前向附近。如果评测仍把向量改成全 0、而线上已经改成默认向量，两个数会不一致，以线上那条为准。

## 方案 C：全 0 换成「新人共享向量」加人群

**做什么。** 全 0 不是「一个普通新人」，只是主网络没怎么见过的一个点，所以分会飘。换两样新参数：

- `e_new`：所有「表里还没有」的 GAID 共用一行，初始用现有 GAID 向量的均值，不要从 0 开始。
- `e_cohort`：按媒体、地域、设备档、小时、行业再加一组小向量。新 GAID 的输入是这两样之和。

这组参数只在冷启动前向里训练（方案 B 的前缀）。老人的私有向量仍然只在已经发布之后使用，并且按已发布点击数往人群收缩：

```text
λ = n / (n + n0)
user = (1 - λ) * e_cohort + λ * e_gaid
```

`n` 用快照里的点击数。`n0`、以及「点击少到多少仍然只用人群」`n_min`，在回放里扫。候选包括「主前向永远不读私有行」、50、200、1000。转化率这么低，私有行要积累很多点击才站得稳。扫出来「完全不读私有行」就能把双空格收回来，说明这只 bug 是格子水平，私有行继续只管老人的排序。

人群向量要新学。工具订阅上，现有的「请求设备标识」打乱之后负样本预估会掉，说明那行现在在抬分，不能直接拿来当新人的先验。

设备标识如果比 GAID 稳（同一个人换了广告 id），冷启动可以再查一层：GAID 没有，就用这个设备上已经发布的点击、购买次数所在的档。用的是次数统计，不是旧的设备向量。标识如果只是机型，并进 `e_cohort` 就行。

**适合。** 希望新人不要全体扣同样的分。高购买人群里的新人和低购买人群里的新人，先验应该不同。双空格的平均被深点用户占着（`v4001=0` 里，当天只点 1 次的行只有 0.8%，点满 32 次的占 46.5%），一张全局扣分会偏向深点用户。

**代价。** 比方案 A 多一组参数，也要和方案 B 一起训，否则主体仍会绕开这组向量。

**算对。** 和 A 同一套冷启动指标。再加一张切片：各媒体、各地域上新人的 cvr_diff。某一档被全局均值压过头，就加大这一档人群向量的容量，而不是把所有人再扣一刀。

## 方案 D：用「已经入库的点击次数」代替 4001

**做什么。** 4001 空着，缺的是「已经点了很多次」这个事实。这个数不必等 UPS，也不必在点击瞬间知道。CVR 样本一入库，就给这个 GAID 的计数加一，写成一张小表，和主模型分开发布。线上查的是**上一版小表**里的次数档：1、2–3、4–12、13–31、≥32，和纪要里的分桶一致。

模型读的是档位，不是这个人自己的购买率。某一档的分数，用这一档里所有人的成熟购买标签来学（做法同方案 A，主体冻住）。一个人前几次已发布的点击，用的是历史上所有人在这个档位的水平。

训练和线上用同一个时间点的次数：时刻 t 只能看到 t 之前已经发布的点击。用「当天结束时一共点了多少」当特征，模型会记住「点满 32 次就压分」，线上第 5 次点击却还在更小的档里，格子再次对不上。这和「训练读到了向量、线上是 0」是同一类错。

点击瞬间只改计数，不改分数。档位的权重来自窗口成熟之后的购买标签，窗口和主头一致。

**适合。** 点击样本虽然做不到实时，但延迟明显短于这一串点击的时长。L 用两档先在 trace 上回放：1 小时、24 小时。只有 1 小时那档能把 k≥4 的 excess 收回来，这张表就值得按小时发布。24 小时那档已经够，表上先只保留「这个人进没进过任一版快照」一个比特，等样本变快，细档位自动生效。

**代价。** 多一张按 GAID 的小表。表可以比完整 MMoE 换得勤，因为它只是计数。第一簇点击在小表发布之前，仍然走方案 A 或 C 的 0 档。

**算对。** 在「次数用滞后 L 重建」的前向上，k≥4 的双空格 cvr_diff 相对 k=1 有额外的、方向正确的下降，同时 k=1 不被这张表误伤（k=1 的次数档就是 0）。

## 方案 E：用展示次数，完全不看点击样本

**做什么。** 竞价请求里就有 GAID，bidder 自己累加「这个 GAID 最近被看过几次」，按小时或当天做成档位。这条链路不经过点击样本，也不经过 4001。

档位只和「GAID 不在表里、4001/902 仍为空」一起用，加在 logit 上，权重照样冻住主体来学。学出来的符号如果是「展示越多分越高」，这张表不上。

**适合。** 点击样本要等很久，方案 D 在一天之内帮不上。深点用户的展示次数只会更高，所以这是「点了很多次但点击特征还是 0」的一个替身。

**代价。** 展示多，可能只是这个人看得多、点得少，不一定是「点了不买」。所以限制在点击特征为空的新人上，并且用留出的 GAID 看符号和分档曲线。计数不需要精确，档位容得下漏计。

**算对。** 和方案 D 相同：深点档比第一档更接近实际，第一档保持方案 A/C 的水平。

## 方案 F：新人走一个小网络

**做什么。** 老人继续用现在的 MMoE。GAID 不在表里时，加一个小头，输入只有请求上一定有的东西：媒体、计划、素材、设备档、地域、小时、行业，以及方案 D/E 的档位（有的话）。小头输出加到 logit 上。购买头上的这层修正不写回 GAID 行。

如果 GAID 行是点击目标和购买目标共用的，这一点尤其有用：深点用户的点击梯度会把共享行往「爱点」推，和购买头要的方向相反。小头只吃购买标签，就不跟点击头抢这一行。

**适合。** 方案 A 的表拟合不好：留出的人里残差很大，而且随广告计划、素材明显弯曲。按计划把 excess 累加起来，如果集中在少数计划上，优先把计划 id 加进方案 A 的键，不必先上小网络。切片很平、表又拟合不好，再上小网络。

**代价。** 多一个头，训练样本必须是冷启动前向。这个头在训练里很少被走到，线上一开就是没训过的支路。

**算对。** 冷启动指标好于方案 A，AUC 仍守住 0.01。好于 A 的部分要来自留出的计划和留出的 GAID，防止小头记住了几个大计划。

## 方案 G：把老人 GAID 向量的压分，蒸馏到上下文上

**做什么。** 8e8 说明 GAID 向量会压分，但新人没有这行。用老人做老师：在老人身上算出「有这行向量」和「拿掉这行向量」的 logit 差，让一个小模型只用上下文去预测这个差。线上新人没有私有向量时，直接用预测出的差。

小模型的输入里不放 GAID，也不放 4001/902。它学的是「哪类流量上，GAID 向量通常会把分压下去」，不是「这个人已经点了很多次」。

**适合。** 方案 C 的人群向量太粗，而压分又确实集中在某些媒体、计划上。它是方案 C 和方案 F 之间的一档：监督信号来自 GAID 向量已经学到的压分，比直接用购买标签更贴这只 bug。

**代价。** 老师信号要用「评估日没有进训练」的老人来做，避免把 8e8 那种当天记忆蒸馏进上下文。蒸馏不了的那部分是纯个人的，仍然只在下一版私有向量里。

**算对。** 新人双空格上，蒸馏头收回的 cvr_diff 接近这些上下文档里老人的压分幅度。收回不了的个人部分，留在方案 B 的下一版向量里，不要求第一天就对齐到 +12%。

## 怎么搭

六种搭法，按手上的数据条件选，不必六套一起上。

1. **只想先压住高一倍，改动最小。** 方案 A。线上 miss 时加一档 logit。同时用留出的人看 k=1 和 k≥32，决定要不要往下走。
2. **希望训练和线上以后对齐。** 方案 B + 方案 A。B 负责「前向看见的输入和线上一样」，A 负责这一格的水平。
3. **希望新人之间有差别。** 把搭法 2 里的 A 换成方案 C。设备 id 能对上「换了 GAID」的人，再加一层设备次数回退。
4. **点击样本大约一小时内能入库。** 搭法 2 或 3，加上方案 D。0 档仍用 A/C，后面的档用已发布次数。
5. **点击样本要等一天，第一天必须压深点用户。** 用方案 E 代替方案 D。E 不依赖点击样本。
6. **一张表拟合不好，而且偏差跟着计划、素材变。** 在搭法 2 上加方案 F 或方案 G。先看 excess 按计划的分布：集中就扩 A 的键，铺平再加头。

不管哪一搭，验收都看**和线上相同的那条输入**，并保留一条暖前向做对照。暖前向选「eval 当天没有进训练」的日子。8e8 同日的 +12% 是上界。

要先量的三个数，决定用 4 还是 5：

- 线上请求里，GAID 不在表里的占比（方案 B 的掩码比例跟它走）
- 点击发生到 CVR 样本可见，要多久（短则 D，长则 E）
- 点击发生到 4001/902 可见，要多久（用来解释现在为什么空，不决定方案）

## 先别做的

- 点击一到就给 GAID 行打负梯度。购买结果还没有，会把后来会买的人一起打下去。
- 随机 dropout GAID 向量。丢掉的是老人，填不满新人前缀的分布。
- 用单个 GAID 的购买率当第一天的主修正。几十次点击移不动带先验的收缩估计。
- 扣分表和主体、GAID 行一起训，指望表自己留在 logit 上。
- 用 8e8 当天的 +11.9% 当新人目标。

## 和现有实验的关系

方案 A 的基线就是现在的 mask 评测。四宫格里除了双空，`4001=0 且 902 非空` 在 mask 下仍有 **+37.5%**，`4001 非空且 902=0` 从 +16% 到 **+58%**。表的键要把这两格包括进去，不单做双空。

工具订阅那篇里，请求与设备打乱后负样本预估上升大约 20%，和「拿掉 GAID 行，分数升高」是同一个方向。那篇看的是老人身上谁在抬分；这篇看的是这行向量线上不存在时分落在哪里。正在跑的置零追训可以继续，它和冷启动前缀不是同一分布。
